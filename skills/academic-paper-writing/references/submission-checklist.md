# Pre-Submission Checklist

Use this checklist before every submission. Check items in order—earlier items often reveal issues that affect later ones.

## 1. Content and Claims

### Narrative
- [ ] Paper has 1-3 specific, concrete claims
- [ ] Claims are actually novel (not restating prior work)
- [ ] Each claim is supported by explicit evidence in the paper
- [ ] Claims are appropriately calibrated to evidence strength

### Abstract
- [ ] Stands alone (reader understands contribution without paper)
- [ ] One paragraph, 4-6 sentences
- [ ] Includes at least one concrete result (number/metric)
- [ ] States the standard of evidence (preliminary vs. systematic)
- [ ] No undefined jargon
- [ ] Within word limit (typically 150-250 words)

### Introduction
- [ ] Opens with motivation (why should anyone care?)
- [ ] Situates work in broader context
- [ ] States contributions explicitly
- [ ] Ends with bullet-point contributions list
- [ ] Key prior work cited appropriately
- [ ] Reader can understand main claims without reading rest

### Methods
- [ ] Sufficient detail for replication
- [ ] All hyperparameters reported (or in appendix)
- [ ] Non-obvious choices justified
- [ ] Notation consistent throughout

### Results
- [ ] Each experiment tied to a specific claim
- [ ] Results include uncertainty (std, CI, etc.)
- [ ] Baselines are strong and fairly implemented
- [ ] Negative results reported honestly
- [ ] Statistical significance reported where appropriate

### Limitations
- [ ] Section exists and is substantive
- [ ] Scope limitations acknowledged
- [ ] Potential failure modes discussed
- [ ] Assumptions stated explicitly

### Related Work
- [ ] Key prior work cited
- [ ] Differences from prior work clear
- [ ] Not misrepresenting others' contributions
- [ ] Concurrent/parallel work acknowledged

## 2. Figures and Tables

### All Figures
- [ ] Every figure has a caption
- [ ] Captions are self-contained (understandable alone)
- [ ] Referenced in text (Figure 1, not "the figure below")
- [ ] Legible at printed size
- [ ] No text on gray backgrounds
- [ ] Line thickness ≥ 0.5pt

### Plots
- [ ] Axis labels present and clear
- [ ] Units specified where applicable
- [ ] Legend explains all elements
- [ ] Error bars/shading for uncertainty
- [ ] Colorblind-accessible (not red-green only)
- [ ] Works in grayscale

### Tables
- [ ] Caption above table
- [ ] Column headers clear
- [ ] Best results bolded
- [ ] Uncertainty reported (± std)
- [ ] Notes explain abbreviations

## 3. Writing Quality

### Clarity
- [ ] No undefined acronyms (define on first use)
- [ ] Technical terms defined before use
- [ ] One idea per sentence
- [ ] Paragraphs have clear topic sentences
- [ ] Transitions between sections

### Style
- [ ] Active voice predominates
- [ ] Consistent terminology (no unexplained synonyms)
- [ ] Hedging matches uncertainty
- [ ] No empty intensifiers ("very," "significant" without meaning)

### Grammar and Polish
- [ ] Spell-checked
- [ ] Grammar-checked
- [ ] Read aloud for flow
- [ ] Citations formatted correctly

## 4. Formatting Compliance

### Document
- [ ] Correct template for venue and year
- [ ] PDF format only
- [ ] Type-1 fonts (check with `pdffonts`)
- [ ] US Letter page size (or A4 if required)
- [ ] Two-column format
- [ ] 10pt body font

### Page Limits
- [ ] Main body within limit (count carefully!)
- [ ] References start on new page (if required)
- [ ] Appendices follow references
- [ ] File size under limit

### Anonymization (Blind Review)
- [ ] No author names on title page
- [ ] No author names in headers/footers
- [ ] No acknowledgments section
- [ ] No grant numbers
- [ ] Self-citations in third person
- [ ] No URLs linking to personal sites
- [ ] No identifying file metadata
- [ ] Supplementary material anonymized

### References
- [ ] APA format (or venue-specific)
- [ ] Page numbers included where available
- [ ] Venue names complete (not just "arXiv")
- [ ] No broken/duplicate entries
- [ ] All cited works appear in references
- [ ] No uncited entries in references

## 5. Reproducibility

### Code
- [ ] Code submitted/linked (if required or encouraged)
- [ ] Code anonymized (no author info)
- [ ] README with setup instructions
- [ ] Dependencies listed
- [ ] Runs on fresh machine

### Data
- [ ] Dataset sources cited
- [ ] Preprocessing described
- [ ] Train/val/test splits specified
- [ ] Random seeds reported

### Experiments
- [ ] Hardware/compute resources described
- [ ] Training time reported
- [ ] All hyperparameters listed
- [ ] Evaluation protocol complete

## 6. Supplementary Material

- [ ] Anonymized
- [ ] In allowed format (PDF, zip, etc.)
- [ ] Size under limit
- [ ] Main paper stands alone without it
- [ ] Referenced from main paper where appropriate

## 7. Final Checks

### Co-author Review
- [ ] All authors have read final version
- [ ] All authors approved submission
- [ ] Author order and affiliations correct

### Submission System
- [ ] Title matches paper
- [ ] Abstract in system matches paper
- [ ] Keywords/topics selected
- [ ] Conflicts of interest declared
- [ ] Supplementary material uploaded

### Last-Minute
- [ ] Downloaded and opened submitted PDF
- [ ] PDF displays correctly (no missing fonts/figures)
- [ ] Page count verified
- [ ] No "Submission copy" or "Under review" watermarks remaining on camera-ready

## Quick Pre-Upload Test

Open your PDF and verify:

1. **Page 1:** No author names, correct title, abstract readable
2. **Page 2-3:** Introduction has contributions list, reads clearly
3. **Middle:** Figures/tables are legible, have captions
4. **End:** References look complete, limitations discussed
5. **Throughout:** No "???" placeholders, no "TODO" comments

## Camera-Ready Specific

- [ ] Author names and affiliations added
- [ ] Acknowledgments added
- [ ] Reviewer suggestions addressed (or justified)
- [ ] Copyright/license info correct
- [ ] Final page limit met (usually +1 page allowed)
- [ ] No major changes from reviewed version
