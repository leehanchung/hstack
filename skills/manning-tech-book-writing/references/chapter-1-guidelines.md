# Chapter 1 Guidelines

Chapter 1 sets clear expectations and motivates readers by answering fundamental questions about your technology.

## Essential Goals

Chapter 1 must accomplish these critical objectives:
- Set clear expectation of what readers will learn
- Provide high-level overview of the topic
- Motivate readers by identifying specific benefits
- Answer: "What is it?", "Why should I care?", and "How does it work?"

## Required Elements (10-15 pages total)

### 1. Opening Bullets
- Start with "This chapter covers" (no colon)
- 3-5 short statements about chapter content
- Use -ing verbs where sensible
- Each bullet fits on one line (~80 characters)

### 2. Chapter Introduction (2-6 paragraphs)
Hook readers immediately with:
- Concrete example or relatable story
- Clear problem statement
- Preview of what's coming

Address these questions concisely:
1. **What is the technology?**
   - Define at high level
   - Position in landscape vs alternatives
   
2. **What are the benefits?**
   - Establish the need
   - Real problems it solves
   - Why readers should care
   - When NOT to use it
   
3. **What's this book's goal?**
   - Target audience (job titles, skillsets)
   - Skills readers will gain
   - How book teaches (single project vs multiple examples)

### 3. Section 1.1: What is [Technology]? (3-5 pages)
- Clear definition (category + differentiation)
- Concrete, relatable example
- Show how it differs from traditional approaches
- Position within larger context
- May include brief prerequisite review if needed

### 4. Section 1.2: Benefits and Use Cases (2-4 pages)
- Most important uses with concrete examples
- How it's different/better than alternatives
- Clear counter-examples where it doesn't fit
- Highly motivating content

### 5. Section 1.3: Mental Model (4-8 pages)
The mental model provides end-to-end system overview:
- Text description of concrete example scenario
- Diagram showing all components
- Annotations showing data flow/operation
- Rich caption guiding through operation
- Complete explanation of components

Example scenarios should be:
- Simple and immediately understandable
- Relevant to reader's likely use cases
- Require no domain-specific knowledge

### 6. Section 1.4: What You Need (1-2 pages)
- Tools, frameworks, languages, platforms required
- Costs involved (free/open source/proprietary)
- Specific paradigms or architectures
- Your book's chosen toolkit and why

### 7. Section 1.5: How This Book Teaches (< 1 page)
- Distinctive teaching strategies
- Single vs multiple examples
- Projects and exercises
- Special features

### 8. Summary Bullets
- Complete sentences summarizing key points
- Can be multiple sentences per bullet
- Restate all important takeaways

## What Does NOT Belong in Chapter 1

Move these to appropriate locations:
- Installation instructions → Appendix
- Detailed chapter roadmap → Front Matter ("About This Book")
- Reader prerequisites → Front Matter
- Tables/reference material → Appendices
- History, theory, philosophy → Only if immediately relevant

## Key Principles

- Readers are busy - get to practical information quickly
- Start with concrete, move to abstract
- Every section needs clear "why should I care?" 
- Use mental models with concrete scenarios
- Provide just enough context to understand, not exhaustive coverage

## Examples from Manning Books

### Good Mental Model Examples:
- Transformer translating English to German phrase
- Solr indexing a tweet
- All show simple, concrete operations through complete system

### Effective Introductions:
- Start with relatable problem or story
- Connect to reader's experience
- Build from familiar to new concepts
