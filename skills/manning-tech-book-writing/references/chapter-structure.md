# Chapter Structure and Checklist

## Essential Chapter Elements

### Style & Formatting Requirements

**Templates and Styles**
- Use correct Manning template
- Apply correct styles for paragraphs, sections, captions
- Format chapter number and title correctly
- Chapter title must be precise and descriptive

**Opening Structure**
- Start with "This chapter covers" (no colon)
- 3-6 opening bullets matching major sections
- Bullets are descriptive phrases, not complete sentences
- Start with -ing verb where sensible
- Each bullet fits on one line (~80 characters)

**Page Guidelines**
- Chapters typically 20-35 pages
- Balance depth with conciseness

### Sections and Headings

**Formatting Rules**
- Use sentence case (only first letter capitalized, except proper nouns)
- Headings must fit on one line
- Apply correct styles for level 1, 2, and 3 headings
- Level 3 headings are unnumbered

**Structure Rules**
- No empty sections
- No stacked headings - always have text between
- If using subheadings, must have at least two (e.g., 1.2.1 requires 1.2.2)

**Content Guidelines**
- Section headings use precise, concise descriptions
- Use active verbs when possible
- Major sections begin with introduction and "why/who cares" statement
- Use subsections and level-3 headings liberally for navigation
- End sections with transitions (unless connection is obvious)

### Browsables (Figures, Tables, Code, Callouts)

**Placement Rules**
- Cannot stack browsables - always have text between
- Same rule as headings: separate with at least one sentence

**Usage Guidelines**
- Use figures to clarify complex concepts
- Code listings should be complete and runnable
- Tables for reference data or comparisons
- Callouts for essential information

### Content Requirements

**Chapter Introduction**
- Define topic briefly
- Provide convincing "why/who cares" statement
- Connect to previous chapters or book's mental model
- Give roadmap of chapter content

**Teaching Approach**
- No fluff - get to practical lessons ASAP
- Minimize history, trivia, edge cases
- Teach with concrete examples/tasks/problems
- Move from concrete to abstract
- End with generalizations, principles, best practices
- Start lessons with diagram/explanation, end with code

**Content Depth**
- Harder topics: more pages, detailed explanations, diagrams, examples
- Easier topics: fewer pages, may skip diagrams/examples if clear
- Define key and new terms
- Make paragraph points evident from beginning

**Information Delivery**
- No frontloading theory
- Deliver information Just-In-Time (JIT)
- Connect to what readers already know

### Tone and Writing Style

**Voice Guidelines**
- Friendly, not stiff or academic
- Active voice, not passive
- "I," "we," and "you" are encouraged
- Brief hooks/stories (1-3 sentences) to introduce topics
- Maintain consistency with MQR throughout

**Clarity Principles**
- Write for your target audience
- Avoid jargon without explanation
- Use analogies to familiar concepts
- Balance technical accuracy with accessibility

### Summary Section

**Format Requirements**
- Always the last section
- No introductory text - just bullets
- Each bullet written as complete sentence(s)
- Multiple sentences per bullet allowed

**Content Requirements**
- Succinctly restate all key takeaways
- Cover major concepts in teaching order
- Focus on applicable knowledge
- Don't just say "we learned" - state the actual learning

## Self-Assessment Checklist

Before submitting, verify:

### Style & Formatting
- [ ] Correct template and styles applied
- [ ] Chapter number and title formatted correctly
- [ ] Opening bullets follow guidelines
- [ ] Page length appropriate (20-35 pages)
- [ ] All headings properly formatted and structured
- [ ] Browsables properly spaced with text between
- [ ] Summary bullets complete and substantive

### Content
- [ ] Introduction hooks reader and provides roadmap
- [ ] Practical lessons delivered quickly
- [ ] Concrete examples throughout
- [ ] Progression from concrete to abstract
- [ ] Appropriate depth for topic difficulty
- [ ] Terms defined when introduced
- [ ] Clear paragraph structure
- [ ] Tone friendly and accessible
- [ ] Sections have introductions and transitions
- [ ] Summary restates all key points

### Teaching Effectiveness
- [ ] Clear "why should I care?" throughout
- [ ] Information delivered just-in-time
- [ ] Examples relevant to target audience
- [ ] Concepts build on previous knowledge
- [ ] Balance of theory and practice
- [ ] Actionable takeaways
